这篇的 frontmatter 声明了 `tool: true`，所以它只会出现在 `/tools/` 与
`/tools/tool-demo/`，不会进首页、分页、归档、分类、标签、RSS、上下篇、相关文章、
随机文章与站点统计。

它同时声明了 `clientIsland: true`。这是另一条正交的轴，只决定渲染模式：带 island
的内容不走 container 预渲染，改在模板里直接渲染 `<Content />`，astro-island 的
component-url 才能解析成建置后带 hash 的资源路径。

下面这颗按钮就是那个 island，水合成功后计数会增加：

<ClientIslandProbe client:load label="点我加一" />

`categories` 与 `tags` 仍然可以保留，工具详情的面包屑与标签会用到它们，但一般
taxonomy 聚合页的来源集合已经先排除工具，所以「测试」分类不会因为这篇而多出一笔
文章。

也因为这样：工具用的分类／标签若没有任何一般文章使用，对应的 taxonomy 页根本不会
产生。呈现层为此不再无条件渲染链接——路由的 getStaticPaths 会算一次
`collectLinkableTaxonomy()`，有页面的渲染成链接，没有的渲染成纯文字。

上面三个标签正好示范两边：「组件」与「测试」是 demo 语料里就有的，渲染成链接；
「工具专用」只有这篇工具在用，渲染成纯文字。分类「测试」同理，面包屑上是可点的。
